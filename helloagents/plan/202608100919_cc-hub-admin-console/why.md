# 变更提案: CC Hub 管理控制台

## 需求背景

OmniDeck 当前只有 Tauri + React 的初始化界面，尚未具备外部服务连接、管理员凭据管理、API 客户端或业务页面。知识库已收录 Claude Code Hub（以下简称 CC Hub）v0.9.2 的管理 REST API；本提案将其接入为一个面向管理员的本地桌面控制台。

用户需要在同一个应用中完成三项日常运维工作：查看、筛选并启停多个上游供应商实例；查看限额用户的额度与用量；持续查看最新使用记录。需求完整性评分为 8/10：功能目标、主要字段和交付形式清晰；目标 CC Hub 实例的实际 OpenAPI schema、部署 URL、管理员凭据和部分统计字段尚需在实施前核验。

术语按现有知识库执行：本提案中的“供应商”固定指 CC Hub 的 `provider` 实例，而不是品牌聚合实体 `vendor`。理由是只有 `provider` 拥有 `isEnabled` 状态和可修改的启停能力。

## 产品分析

### 目标用户与场景

- **用户群体:** 持有 CC Hub 管理员权限、需要在 Windows 桌面端日常查看上游健康和用量的运维人员。
- **使用场景:** 在工作时间快速定位某类 provider、暂停或恢复单个 provider、识别接近总额度的用户，并观察最近产生的 API 使用记录。
- **核心痛点:** 现有 OmniDeck 没有连接能力；管理员令牌不应放进 WebView 存储；多个页面若各自直连上游，会产生认证、CORS、字段口径和刷新行为不一致的问题。

### 价值主张与成功指标

- **价值主张:** 在不暴露管理员令牌给渲染层的前提下，提供统一、可恢复、可观察的 CC Hub 管理视图。
- **成功指标:** 已配置且通过校验的 CC Hub 实例中，管理员能在一次加载内看到 provider 列表与已确认的今日调用次数；能成功切换单个 provider 的启用状态；能在限额页看到所需五项额度数据；使用详情页在当前最新页每 10 秒无重叠地刷新一次。

### 人文关怀

- 不在 UI、日志、测试夹具或错误提示中显示 `ADMIN_TOKEN`、明文 provider key、用户 API key 或上游原始错误详情。
- 对加载失败、权限不足、空数据和无法确认的上游字段提供明确状态，避免把缺失数据伪装成零值或“不限”。

## 变更内容

1. 新增单个 CC Hub 连接配置：保存基地址和管理员令牌，连接元数据与令牌分离存放；令牌仅由 Tauri Rust 宿主读取。
2. 新增供应商实例页面：按名称和 `providerType` 筛选，支持启用状态筛选、刷新、单个启停，以及展示已核验来源的今日调用次数。
3. 新增限额管理页面：分页查看用户，并展示已用额度、总额度、今日使用额度、当月使用额度和剩余额度。
4. 新增使用详情页面：按已确认的日志字段筛选和分页查看最新记录；仅在最新页启用 10 秒轮询，并防止重复并发请求和陈旧响应覆盖。
5. 新增固定业务命令的 CC Hub Rust 适配层、前端类型/状态层、测试夹具和模块知识库说明。

## 范围边界

- **范围内:** 一个已配置 CC Hub 实例的管理员连接；CC Hub v1 API 的 provider 列表/筛选/启停、用户限额只读汇总、使用日志只读详情；连接测试、错误状态、手动刷新和使用详情自动刷新。
- **范围外:** Sub2API 接入；多个 CC Hub 环境或连接配置档案；`vendor`/endpoint 的创建、编辑、测活和熔断控制；provider 创建、删除、批量修改；用户或 key 的额度编辑、重置、删除；使用记录导出；实时 WebSocket/SSE；明文密钥展示；服务端或 CC Hub 数据库迁移。
- **拆分说明:** 三个页面共享同一个安全连接边界、认证模型、时间口径与 API 适配层，可构成“CC Hub 管理控制台”这个单一可验证闭环。更广的配置写入、vendor/endpoint 管理和多实例支持将作为后续独立方案包处理。

## 影响范围

- **模块:** Tauri 宿主命令与安全存储、CC Hub HTTP 适配、React 应用壳、供应商管理、限额管理、使用详情、测试与知识库。
- **文件:** 现有 `src/App.tsx`、`src/App.css`、`src/App.test.tsx`、`src-tauri/Cargo.toml`、`src-tauri/src/lib.rs`；新增 `src/features/cc-hub/**`、`src-tauri/src/cc_hub/**`、测试夹具与模块文档。
- **API:** 仅调用 CC Hub `/api/v1/*` 的已列明端点；OmniDeck 不对网络公开新的 HTTP API，而是通过 Tauri `invoke` 提供固定业务命令。
- **数据:** 本地仅持久化非敏感连接元数据；管理员令牌进入操作系统凭据库。无业务数据库迁移。

## 核心场景

### 需求: 建立受保护的 CC Hub 管理连接

**模块:** Tauri 宿主与连接设置

管理员填写 CC Hub 基地址和 `ADMIN_TOKEN` 后，应用验证 API 版本、管理员权限和必要 endpoint/schema；成功后只显示已配置状态和基地址，不能读取回令牌。

#### 场景: 连接校验成功

- 已提供可访问的 CC Hub 基地址和具有 admin 权限的 Bearer token。
- 应用通过 Rust 宿主调用健康、OpenAPI 和最小管理员读取请求。
- 基地址以规范化形式保存，令牌仅写入系统凭据库，前端获得脱敏的连接状态。

#### 场景: 连接校验失败

- 基地址不可达、TLS 失败、token 无效、token 无 admin 权限，或运行实例的必要 schema 不满足本提案要求。
- 应用保留用户可修正的非敏感配置输入，不保存未通过校验的连接，也不显示上游 `detail` 或 token。

### 需求: 查看和控制供应商实例

**模块:** 供应商管理

管理员可以查看 CC Hub 返回的多个 `provider`，按名称、类型和启用状态收窄结果，查看每个 provider 的启用状态和今日调用次数，并使用开关改变单个 provider 的状态。

#### 场景: 筛选供应商

- 已建立有效管理员连接。
- 管理员输入关键词或选择 `providerType`、启用状态。
- 列表调用 `GET /api/v1/providers` 的已确认筛选参数，并只在本地应用未由上游支持的状态筛选；界面显示加载、空态或错误态。

#### 场景: 启停单个供应商

- 供应商行显示可操作的 `isEnabled` 开关。
- 管理员改变开关后，应用仅提交该 provider 的最小 PATCH；请求进行期间该行锁定。
- 上游成功响应的 `isEnabled` 与目标状态一致时更新列表；失败或不一致时恢复原状态并显示脱敏错误。

#### 场景: 显示今日调用次数

- provider 列表加载了 `include=statistics`，或已确认的 provider 维度统计端点可用。
- 应用按目标实例 OpenAPI/脱敏样本确认的顶层 `todayCallCount:number` 映射今日调用次数。
- 不存在可验证的 provider 维度今日请求数时，实施被契约门阻断，不以未分页日志条数伪造调用次数。

### 需求: 查看限额用户的额度情况

**模块:** 限额管理

管理员可以分页查看用户，并为每位用户看到已用额度、总额度、今日使用额度、当月使用额度和剩余额度。

#### 场景: 加载一页用户额度

- 管理员打开限额管理页，可使用名称/状态等已确认的用户列表筛选。
- 应用先获取用户分页，再以最多 4 个并发的 `limit-usage:all` 请求填充额度桶；`users:usageBatch` 的按 key 今日统计不用于本页。
- 总额度和已用额度来自 `limitTotal`，今日使用额度来自 `limitDaily`，当月使用额度来自 `limitMonthly`；剩余额度由总额度的 `limit - usage` 派生。

#### 场景: 处理无限额、未知和超额

- 目标实例中 `limit:null` 明确表示该桶未配置额度上限，页面展示“不限”；字段缺失或类型不匹配时展示“不可用”，而非零。
- 用量大于总额度时，剩余额度显示为零，并保留超额状态提示；不丢失原始差额用于状态判断。
- 金额单位以目标实例确认的显示设置和上游成本桶语义为准，默认不擅自将 USD 换算为其他币种。

### 需求: 查看持续刷新的使用详情

**模块:** 使用详情

管理员可以查看最新使用记录，并在使用详情页处于可见的最新页时自动获取新数据。

#### 场景: 查询和展示最新使用记录

- 管理员打开使用详情页，选择已确认支持的时间、provider、用户、模型或状态过滤条件。
- 应用请求 `GET /api/v1/usage-logs`，使用目标实例确认的分页和排序语义显示规范化日志行。
- 不为每行额外请求用户或 provider；优先使用日志中已有字段和本地已加载的名称映射。

#### 场景: 定时刷新最新页

- 页面停留在最新页、自动刷新已开启且应用窗口可见。
- 应用每 10 秒发起一次刷新；上一次请求未结束时跳过本轮；筛选、分页、离开页面、窗口隐藏或组件卸载时使在途请求失效并停止后续调度。宿主请求可能完成，但其结果必须被丢弃。
- 每次以最新响应替换当前最新页；使用稳定日志 ID 或已核验的等价键去重，旧响应不得覆盖更新后的筛选结果。

## 风险评估

- **风险:** CC Hub 的运行时 schema 可能与静态文档或未来升级版本漂移；provider PATCH 已在授权的非关键停用 provider 上完成一次保持状态的真实回执核验，但上游升级后仍需重新验证。  
  **缓解:** 使用不含敏感内容的 OpenAPI/响应 fixture 做严格解析与回归测试；运行时能力标记仅在最小可逆 PATCH 返回并复读一致时开启。
- **风险:** `ADMIN_TOKEN` 是高权限凭据，前端直连会受 CSP/CORS 影响且容易进入 bundle、localStorage 或日志。  
  **缓解:** 固定 Tauri Rust 命令加 `reqwest` 客户端；令牌放 OS credential store；不提供任意 URL/请求头转发命令；维持现有 WebView CSP。
- **风险:** provider 开关会改变上游流量路径。  
  **缓解:** 仅允许单行、最小字段、可逆的 PATCH；行级 pending 锁定；以服务端返回状态为准并保留上游 operation/undo 元数据供诊断但不暴露敏感信息。
- **风险:** 每页用户逐个取额度可能对 CC Hub 造成突发请求。  
  **缓解:** batch 响应不完整时固定使用最多 4 个并发的逐用户请求、25 条默认页大小、结果失效和短期缓存，避免突发负载。
- **风险:** “今日”使用本地时区会与 CC Hub 计费窗口不一致。  
  **缓解:** 使用 `/api/v1/system/timezone` 的服务器时区或上游直接聚合值，统一计算与显示日期边界。
- **风险:** 日志轮询可能重复请求、覆盖新筛选结果或误把数据缺失当作无使用。  
  **缓解:** 仅刷新可见的最新页，使用请求序号、稳定键、宿主请求超时和明确的加载/错误/陈旧状态；请求失效后只丢弃结果，不假定前端可中止宿主网络调用。
